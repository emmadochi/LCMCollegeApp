# LCM College — Deployment Guide (Google Play Store)

A complete, step-by-step guide to deploy the LCM College Flutter application to the Google Play Store.

---

## Prerequisites

Before beginning, ensure the following are in place:

- A **Google Play Developer Account** (one-time $25 fee at [play.google.com/console](https://play.google.com/console))
- **Android Studio** or **Java JDK 11+** installed (for the `keytool` command)
- **Flutter SDK** installed and configured on your machine

---

## Phase 1: Sign Your App

The Play Store **requires** all apps to be signed with a production keystore. The debug-signed APK generated by `flutter build apk` is **not accepted** by the Play Store.

### Step 1 — Generate a Keystore

Open a terminal in the project root and run:

```bash
keytool -genkey -v -keystore android/upload-keystore.jks -storetype JKS -keyalg RSA -keysize 2048 -validity 10000 -alias upload
```

You will be prompted to provide:
- A **keystore password**
- A **key password** (can be the same)
- Your **name, organization, and country**

> **⚠️ IMPORTANT:** Back up `upload-keystore.jks` and the passwords securely. Losing them means you can **never update** your app on the Play Store.

---

### Step 2 — Create `android/key.properties`

Create a new file at `android/key.properties` with the following content:

```properties
storePassword=<your-keystore-password>
keyPassword=<your-key-password>
keyAlias=upload
storeFile=../android/upload-keystore.jks
```

> **⚠️ SECURITY:** Add both `key.properties` and `upload-keystore.jks` to your `.gitignore` immediately to prevent exposing secrets on GitHub.

---

### Step 3 — Configure `android/app/build.gradle`

**Add the following BEFORE the `android {}` block:**

```groovy
def keystoreProperties = new Properties()
def keystorePropertiesFile = rootProject.file('key.properties')
if (keystorePropertiesFile.exists()) {
    keystoreProperties.load(new FileInputStream(keystorePropertiesFile))
}
```

**Add a `signingConfigs` block INSIDE the `android {}` block:**

```groovy
signingConfigs {
    release {
        keyAlias keystoreProperties['keyAlias']
        keyPassword keystoreProperties['keyPassword']
        storeFile keystoreProperties['storeFile'] ? file(keystoreProperties['storeFile']) : null
        storePassword keystoreProperties['storePassword']
    }
}
```

**Update the `buildTypes.release` section:**

```groovy
buildTypes {
    release {
        signingConfig signingConfigs.release
        minifyEnabled true
        shrinkResources true
        proguardFiles getDefaultProguardFile('proguard-android.txt'), 'proguard-rules.pro'
    }
}
```

---

## Phase 2: Prepare the App for Release

### Step 4 — Bump the App Version

In `pubspec.yaml`, update the version before every release:

```yaml
version: 1.0.0+1
# format: versionName+versionCode
# - versionName (1.0.0) shown to users
# - versionCode (+1) must increment with every Play Store upload
```

---

### Step 5 — Verify App Configuration

| Configuration | Location | Example |
|---|---|---|
| **App Name** | `android/app/src/main/AndroidManifest.xml` | `android:label="LCM College"` |
| **Package ID** | `android/app/build.gradle` | `applicationId "com.lcmcollege.app"` |
| **Min SDK** | `android/app/build.gradle` | `minSdkVersion 21` |

> **⚠️ NOTE:** The `applicationId` (Package ID) **cannot be changed** after the app is published. Choose it carefully.

---

### Step 6 — Build the Signed Release

**Option A: App Bundle (Recommended for Play Store)**

Google Play strongly prefers `.aab` as it reduces download size for end users.

```bash
flutter build appbundle --release
```

Output: `build/app/outputs/bundle/release/app-release.aab`

**Option B: APK (For direct/sideload distribution)**

```bash
flutter build apk --release
```

Output: `build/app/outputs/flutter-apk/app-release.apk`

---

## Phase 3: Publish to Google Play Console

### Step 7 — Create Your App

1. Go to [Google Play Console](https://play.google.com/console)
2. Click **"Create app"**
3. Fill in:
   - **App name**: LCM College
   - **Default language**: English (United States)
   - **App or Game**: App
   - **Free or Paid**: Free
4. Accept the declarations and click **"Create app"**

---

### Step 8 — Complete the Store Listing

Navigate to **"Store Presence" → "Main store listing"** and provide:

| Field | Requirement |
|---|---|
| **Short description** | Max 80 characters |
| **Full description** | Max 4000 characters |
| **Phone screenshots** | Minimum 2, maximum 8 |
| **Icon** | 512x512 PNG (use `assets/images/logo.png`) |
| **Feature graphic** | 1024x500 PNG (promotional banner) |

---

### Step 9 — Complete Content Rating

Navigate to **"Policy" → "App content"** and complete the content rating questionnaire.

For LCM College (an educational app), the expected rating is **"Everyone"**.

---

### Step 10 — Set Up Pricing & Distribution

Navigate to **"Monetize" → "Pricing & distribution"**:

1. Set the app to **Free**
2. Select target **countries or regions**
3. Confirm the distribution settings

---

### Step 11 — Upload Your Build

1. Navigate to **"Testing" → "Internal testing"** (recommended for first release) OR **"Release" → "Production"**
2. Click **"Create new release"**
3. Upload your `app-release.aab` file
4. Fill in the **Release notes** (e.g., *"Initial release of LCM College"*)
5. Click **"Save"** then **"Review release"**

---

### Step 12 — Submit for Review

1. Review the pre-launch report on the release summary page
2. Click **"Start rollout to Production"** (or the relevant track)
3. Google will review the app — this typically takes **1–3 business days** for new apps
4. You will receive an email notification once it is approved and live

---

## Phase 4: Post-Deployment

### Step 13 — Monitor the App

Use the **Google Play Console** to monitor key metrics:
- **Android Vitals**: Crash rates, ANR (App Not Responding) rates
- **Ratings & Reviews**: User feedback and star ratings
- **Statistics**: Install counts, active users, revenue (if applicable)

---

### Step 14 — Release Future Updates

For every update:

1. Increment the `versionCode` in `pubspec.yaml` (e.g., `1.0.0+2` → `1.0.1+3`)
2. Make your code changes
3. Run `flutter build appbundle --release` again
4. Go to Play Console → **"Production"** → **"Create new release"**
5. Upload the new `.aab` and add release notes
6. Submit for review

---

# iOS Deployment Guide (Apple App Store)

> **⚠️ REQUIREMENT:** iOS builds **must** be compiled on a **macOS machine** with Xcode installed. You cannot build a release iOS app from Windows.

---

## iOS Prerequisites

- A **Mac computer** running macOS 13 (Ventura) or later
- **Xcode 15+** installed from the Mac App Store
- An **Apple Developer Account** ($99/year at [developer.apple.com](https://developer.apple.com))
- An **Apple ID** enrolled in the Apple Developer Program
- Flutter installed on the Mac

---

## Phase 1: Configure Apple Developer Account

### Step 1 — Register a Bundle ID (App ID)

1. Go to [Apple Developer Portal](https://developer.apple.com/account)
2. Navigate to **"Certificates, Identifiers & Profiles" → "Identifiers"**
3. Click **"+"** to register a new App ID
4. Select **"App"** and click **Continue**
5. Enter a **Description** (e.g., LCM College)
6. Set **Bundle ID** to **Explicit** and enter your ID (e.g., `com.lcmcollege.app`)

   > **⚠️ IMPORTANT:** This Bundle ID must match the `PRODUCT_BUNDLE_IDENTIFIER` in your Xcode project and **cannot be changed** after App Store submission.

7. Enable any required **Capabilities** (e.g., Push Notifications, Sign In with Apple)
8. Click **Continue** then **Register**

---

### Step 2 — Create a Distribution Certificate

1. In the Apple Developer Portal → **"Certificates"** → click **"+"**
2. Select **"Apple Distribution"** under Software
3. Follow the on-screen instructions to generate a **Certificate Signing Request (CSR)** from your Mac using **Keychain Access**
4. Upload the CSR and download the generated `.cer` certificate
5. Double-click the downloaded `.cer` file to install it in your Mac's Keychain

---

### Step 3 — Create a Provisioning Profile

1. In the Apple Developer Portal → **"Profiles"** → click **"+"**
2. Select **"App Store Connect"** under Distribution
3. Select your **App ID** (from Step 1)
4. Select the **Distribution Certificate** (from Step 2)
5. Name the profile (e.g., `LCM College App Store`) and click **Generate**
6. Download and double-click the `.mobileprovision` file to install it

---

## Phase 2: Configure the Xcode Project

### Step 4 — Open the Project in Xcode

On your Mac, navigate to your project and open the iOS workspace:

```bash
cd /path/to/CollegeApp
open ios/Runner.xcworkspace
```

> **⚠️ NOTE:** Always open the `.xcworkspace` file, NOT the `.xcodeproj` file.

---

### Step 5 — Configure Signing & Capabilities

1. In Xcode, click the **"Runner"** project in the left sidebar
2. Select the **"Runner" target** → **"Signing & Capabilities"** tab
3. Set **Team** to your Apple Developer account
4. Ensure **Bundle Identifier** matches your registered App ID (e.g., `com.lcmcollege.app`)
5. Under **Signing**, select **"Automatically manage signing"** for simplicity

   OR manually select:
   - **Provisioning Profile**: The profile created in Step 3
   - **Signing Certificate**: Your Distribution certificate

---

### Step 6 — Set App Version & Build Number

In Xcode → **"Runner" target** → **"General"** tab:

- **Version**: e.g., `1.0.0` (shown to users on the App Store)
- **Build**: e.g., `1` (must be incremented with every TestFlight/App Store upload)

Alternatively, update `pubspec.yaml` — Flutter syncs these values automatically:

```yaml
version: 1.0.0+1
# versionName = 1.0.0
# versionCode/Build Number = 1
```

---

## Phase 3: Build for Release

### Step 7 — Build the IPA via Flutter

Run the following on your Mac terminal from the project root:

```bash
flutter build ipa --release
```

Output: `build/ios/ipa/LCM College.ipa`

OR build from Xcode directly:

1. In Xcode, set the scheme to **"Runner"** and destination to **"Any iOS Device (arm64)"**
2. Menu → **"Product" → "Archive"**
3. This will open the **Organizer** window when complete

---

## Phase 4: Submit to App Store Connect

### Step 8 — Create Your App on App Store Connect

1. Go to [App Store Connect](https://appstoreconnect.apple.com)
2. Click **"My Apps"** → **"+"** → **"New App"**
3. Fill in:
   - **Platforms**: iOS
   - **Name**: LCM College
   - **Primary Language**: English (U.S.)
   - **Bundle ID**: Select your registered Bundle ID
   - **SKU**: A unique internal identifier (e.g., `lcmcollege001`)
4. Click **Create**

---

### Step 9 — Complete the App Store Listing

Navigate to your app → **"App Store"** tab and fill in:

| Field | Requirement |
|---|---|
| **Name** | Max 30 characters |
| **Subtitle** | Max 30 characters (optional) |
| **Description** | Max 4000 characters |
| **Keywords** | Max 100 characters, comma-separated |
| **Support URL** | A valid URL for user support |
| **Screenshots** | Required for 6.5" iPhone (minimum) |
| **App Icon** | 1024x1024 PNG (no alpha channel) |
| **App Preview** | Optional video previews |

---

### Step 10 — Complete App Information

Navigate to **"App Information"**:

1. Set the **Category** (e.g., Education)
2. Set the **Content Rights** declaration
3. Set **Age Rating** (complete the questionnaire — LCM College will likely be **4+**)

---

### Step 11 — Set Pricing & Availability

Navigate to **"Pricing & Availability"**:

1. Set **Price**: Free
2. Select **Available Territories** (all countries or specific regions)

---

### Step 12 — Upload the Build

**Option A: Via Xcode Organizer**

1. After archiving (Step 7), the Organizer opens automatically
2. Select your archive and click **"Distribute App"**
3. Select **"App Store Connect"** → **"Upload"**
4. Follow the prompts, ensuring signing is correct
5. Click **"Upload"**

**Option B: Via Flutter CLI (uses `xcrun altool` or Transporter)**

```bash
xcrun altool --upload-app -f "build/ios/ipa/LCM College.ipa" \
  --type ios \
  --username "your@apple.id" \
  --password "your-app-specific-password"
```

> **Note:** Use an **App-Specific Password** from [appleid.apple.com](https://appleid.apple.com), not your main Apple ID password.

---

### Step 13 — Add Build to App Store Release

1. Once the build has finished processing in App Store Connect (can take ~15 minutes)
2. Navigate to your app → **"App Store"** → select your version
3. Scroll to **"Build"** section and click **"+"**
4. Select the uploaded build

---

### Step 14 — Submit for Review

1. Complete all required metadata (all red indicators must be resolved)
2. Answer the **App Review Information** questions (demo account, notes for reviewer)
3. Under **"Version Release"**, choose:
   - **Automatically release**: Published immediately after approval
   - **Manually release**: You control when it goes live
4. Click **"Add for Review"** then **"Submit to App Review"**
5. Apple review typically takes **1–3 business days**
6. You will receive an email notification once approved

---

## Phase 5: Post-Deployment (iOS)

### Step 15 — Monitor via App Store Connect

- **Crashes**: View crash logs in Xcode → **"Window" → "Organizer" → "Crashes"**
- **Ratings & Reviews**: Monitor in App Store Connect → **"Ratings & Reviews"**
- **Analytics**: View installs, sessions, and retention in **"Analytics"**

---

### Step 16 — Release Future iOS Updates

For every update:

1. Increment the **Build Number** in Xcode (or `versionCode` in `pubspec.yaml`)
2. Make your code changes
3. Run `flutter build ipa --release` or archive in Xcode
4. Upload the new build via Xcode Organizer
5. Add the build to the new App Store version and submit for review
